# 設計メモ: 正解はn年後

## 1. 何を守るか

- 問題と答えは、設定した期限の前には **作った本人を含めて誰も** 読めないこと。
- サーバー・ログイン・課金なし。運用費ゼロで、ブラウザだけで動くこと。
- 端末を変えても、リンクか文字列さえあれば開けること。

「この画面では隠す」程度の目隠し(ボタンを押せないだけ、localStorage に平文で持つ等)は、
開発者ツールで中身が見えるので不採用。**暗号で、期限前は鍵がこの世に存在しない** 状態を作る。

## 2. 方式の比較

| 方式 | 期限前に開けない根拠 | サーバー | 欠点 |
| --- | --- | --- | --- |
| **A. drand 時限暗号(採用)** | 復号鍵 = 未来の回の drand 署名。まだ誰も作っていない | 不要(公開ビーコンを読むだけ) | drand が続く前提。期限後の復号時にネット接続が必要 |
| B. 時間のかかる計算パズル(RSW など) | 逐次計算に n 年かかる | 不要 | 端末の速さで期限がずれる。n 年間計算し続ける必要があり非現実的 |
| C. 自前サーバーが期限後に鍵を返す | サーバーを信じる | 必要 | 条件の「サーバーなし」「運用費ゼロ」に反する。サーバー停止で永久に開かない |
| D. 端末の時計で判定して隠すだけ | なし(時計を進めれば開く) | 不要 | 「絶対に開けない」を満たさない |
| E. 鍵を第三者に預ける(紙・友人) | 人を信じる | 不要 | 手間。預けた人は期限前に開ける |

→ **A を採用**。B は「n 年」に耐えない、C は条件違反、D・E は「絶対」を満たさない。

## 3. drand 時限暗号のしくみ

- [drand](https://drand.love) は League of Entropy(Cloudflare、Protocol Labs、大学など複数組織)が
  運営する公開ランダムビーコン。**quicknet** チェーンは 3 秒ごとに「回(round)」番号 r に対する
  BLS 閾値署名 σ_r を公開する。署名には参加組織の過半数の協力が要り、未来の回の署名は誰も前もって作れない。
- 署名 σ_r は「ID = r」に対する IBE(ID ベース暗号, Boneh–Franklin)の秘密鍵になっている。
  そのため、**チェーンの公開鍵と回番号 r だけで、σ_r が出るまで誰も開けない暗号文** を今すぐ作れる。
- 実装はプロトコル公式の [tlock-js](https://github.com/drand/tlock-js)(age 形式 + IBE)を使う。

```
作成時(オフラインで可)                      期限後
 問題+答え ──age暗号──► 暗号文             drand から σ_r を取得 ──► 署名を検証 ──► 復号
          ▲                                      (公開鍵で BLS 検証)
  quicknet 公開鍵 + 回 r = 期限の時刻
```

- 回番号: `r = ceil((期限 - genesis) / 3秒) + 1`(drand-client の `roundAt`)。期限の誤差は最大 3 秒。
- 作成時は **ネット通信なし**(公開鍵・genesis・周期はページに固定で埋め込み)。
- 開封時だけ `https://<relay>/<chain hash>/public/<r>` を 1 回読む。リレーは次の順に試す:
  `api.drand.sh` → `api2.drand.sh` → `api3.drand.sh` → `drand.cloudflare.com`。
  取得した署名は、埋め込んだ公開鍵で検証してから使う(リレーが嘘をついても通らない)。
- 通信先は `<meta http-equiv="Content-Security-Policy">` の `connect-src` でこの 4 つに限定する。
  ライブラリはページ内に同梱し、CDN からは読み込まない。

## 4. 持ち出し形式(リンク/文字列)

```
TC1.<表書き base64url>.<age 暗号文(バイナリ) base64url>
リンク: <このページのURL>#TC1....
```

- `#` 以降(フラグメント)はサーバーに送られないので、ページを置いた先にも中身は届かない。
- 暗号文の中身は JSON `{"v":1,"t":表書き,"q":問題,"a":答え,"c":作成日時}`。
- 期限(回番号)は age ヘッダー `-> tlock <r> <chain hash>` から読む。別に持たないので食い違わない。
- 表書き(タイトル)だけは期限前にも見せたいので平文で持つ。暗号文の中にも同じものを入れ、
  開封後は暗号文側を正とする(平文側が書き換えられても中身はだませない)。
- 長さは問題+答えが短文なら 600〜900 文字程度。リンクでも文字列でも同じものを貼れば開ける。

## 5. 通知(サーバーなし)

- 作成直後に **カレンダーファイル(.ics)** を書き出す。期限の日時の予定 + その時刻のアラーム(VALARM)。
  予定の説明と URL 欄にカプセルのリンクを入れるので、通知からそのまま開ける。
- iPhone/Android/PC のカレンダーが通知を担うので、ブラウザを開いていなくてもよい。
- 補助: ページを開いている間は 1 秒ごとにカウントダウンし、期限を過ぎたらその場で「開けられます」に切り替える。
- 不採用: Web Push(プッシュサーバーが要る)、Notification API の予約(ページが閉じると動かない)。

## 6. 端末内の保存

- この端末で作った/開いたカプセルは、**暗号文のまま** localStorage に一覧として残す(端末内の便利機能)。
- 問題・答えの平文は保存しない。作成フォームも作成後に空にする。
- 開封後の「正解した/答えを見た」状態だけ保存する。消えてもリンクがあれば何度でも開ける。

## 7. 答え合わせ

- 開封後はページ内に答えがあるので、照合はブラウザ内で行う(期限後なので隠す意味はない)。
- 表記ゆれを吸収: Unicode NFKC(全角/半角)、英字の大小、カタカナ→ひらがな、空白と句読点(。、.,!?・)を無視。
- 間違えると揺れて再挑戦。1 回間違えたら「答えを見る」を出す。正解は紙吹雪 + 振動(対応端末)。

## 8. 限界とリスク(正直に)

- **drand が止まると永久に開かない。** quicknet は 2023 年開始で、10 年を超える保証はない。
  10 年を超える期限には画面で注意を出す。上限は 30 年にした。
- 開封時にネット接続が要る(署名を取得するため)。一度開けた後の答え合わせは通信しない。
- 「期限前に開けない」は drand の運営組織の過半数が結託しないことが前提(閾値署名の性質)。
- 端末の時計は「開ける」ボタンを出すかの判断にだけ使う。時計を進めても署名がまだ無いので復号はできない。
- 問題を見られないことは守るが、表書き・期限・おおよその文字数は誰でも見られる。

## 9. ライブラリの同梱

index.html 末尾の `<script id="tlock-bundle">` は次で作った(MIT / Apache-2.0)。

```
npm i tlock-js@0.9.0 buffer@6.0.3 esbuild@0.28.2
# entry.js: tlock-js の timelockEncrypt/timelockDecrypt/roundAt/roundTime/Buffer と
#           drand-client の verifyBeacon を window.TL に出すだけ
npx esbuild entry.js --bundle --minify --format=iife --define:global=globalThis --outfile=bundle.js
```

依存: tlock-js 0.9.0, drand-client 1.2.5, @noble/curves 1.9.7, @noble/hashes 1.8.0,
@stablelib/chacha20poly1305 1.0.1, buffer 6.0.3。
